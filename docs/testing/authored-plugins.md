# Agent 编写插件：会话试用与验证

CordiAct 前台会话的 Agent 可以编写插件源码、申请启用、在下一轮调用新增工具。`schemaVersion: 1` 保留原有固定文本格式；`schemaVersion: 2` 可混合固定文本与宿主提供的有界文本变换。不支持加载 JavaScript、TypeScript、Kotlin、Shell、MCP 或任意脚本。与 [插件改造路线](../architecture/plugin-extension.md)配套。

## 用法

在普通前台对话（不是后台任务、子 Agent 或斜杠命令）中发出类似请求：

> 请帮我写一个名为 `release-checklist` 的 CordiAct 纯文本插件。工具 `show` 只返回发布前检查清单。写源码并验证，申请我批准，不要替我批准。

1. Agent 用 `workspace.files.write_text` 写入当前工作区的 `plugins/release-checklist.json`。**这一步只写草稿**，不会加载或启用文件。
2. 调用 `workspace.plugins.author`，参数 `action: inspect, plugin_id: release-checklist`。宿主返回当前原始文件的 SHA-256 和将要公开的工具 ID。错误不回显输入源码。
3. 调用同一工具，参数 `action: activate, plugin_id: release-checklist, sha256: <上一步摘要>`。当前会话的审批卡展示路径、格式版本、摘要、工具名、说明、完整固定输出或变换操作及上限。宿主拒绝未批准、摘要不匹配或提交时会话已不可用的请求。不要把密钥、私人数据放到插件源码或审批预览。
4. 批准后，Agent 下一次在**同一个前台会话**使用 `extension.authored.release-checklist.show`。当前回合的工具目录不会中途扩充。`action: list` 列本会话已启用的版本；`action: deactivate` 带同一插件 ID 和已启用摘要，批准后撤回工具，保留源码。

```json
{
  "schemaVersion": 1,
  "id": "release-checklist",
  "title": "发布前检查",
  "tools": [
    {
      "name": "show",
      "description": "显示发布前检查清单",
      "text": "复核差异\n运行定向测试\n核对 GitHub Actions 产物"
    }
  ]
}
```

### v2：固定文本与文本变换可以放在同一个插件

例如，在当前工作区新建 `plugins/text-cleanup.json`：

```json
{
  "schemaVersion": 2,
  "id": "text-cleanup",
  "title": "文本整理",
  "tools": [
    {"name": "strip", "description": "去掉首尾空白", "kind": "text_transform", "operation": "trim"},
    {"name": "show", "description": "显示说明", "kind": "static_text", "text": "仅处理传入的文本。"}
  ]
}
```

用同样的 `inspect → activate → 下一轮调用` 流程启用。`extension.authored.text-cleanup.strip` 只接受参数 `text`，例如 `{"text":"  你好  "}` 返回 `你好`；空字符串也可用。`uppercase` 和 `lowercase` 用 `Locale.ROOT`，不随手机的地区设置变化。变换输入和输出各限 4096 UTF-8 字节；超限或存在畸形 Unicode 时拒绝，不返回截断的变换结果。整个对话仍受通用工具结果和上下文预算约束，较长或经转义膨胀的内容可能不能完整内联。

两版都限制源码 16 KiB 和 1–4 个工具。插件与工具 ID 为 2–24 位小写标识；标题、说明和固定正文分别限 120、480 和 4096 UTF-8 字节。拒绝未知或重复字段、未知格式版本及不合法的 UTF-8。v1 固定工具无 `kind`；v2 必须明确 `kind`，只能按类型提供 `text` 或 `operation`，不能混用。输出是不可信数据，不会被解释为模板、系统指令、文件读取、网络请求或第二次工具调用。工具本身不联网，但调用返回的数据可能随当前对话发送到配置的模型提供商；停用不删除历史消息。

审批绑定原始字节的摘要与发起它的普通前台回合。切换会话、应用退到后台、停止回合，或一般审批窗口到期（默认 60 秒）后，旧请求不能启用插件；切回原会话也要重新申请。如果审批界面提示该请求已失效或已处理，本次点击未被接受。收到批准不代表发布成功，以回合结果和会话插件清单为准。修改草稿**不会热更新**已启用版本；先撤回旧版本，再检查和审批新版本。重启保留本地草稿，但不恢复激活。

### 不打开模型也能查看和撤回

在当前未归档的用户会话，打开右上角工作台菜单，选择「会话插件」。面板显示本会话插件 ID、已启用版本的 SHA-256 和工具 ID；可刷新后按「撤回」并确认。无需模型配置、联网或复制摘要；此操作不删除草稿、历史记录，也不会停用其他会话的插件。

选择「查看工作区草稿」可分页浏览当前工作区 `plugins/` 顶层符合命名规则的普通 `.json` 文件，不含子目录中的文件。清单只是文件元数据；点击「预览」才校验格式，读取该时刻的 SHA-256、标题、工具及固定输出或变换。一个清单页可能筛不出草稿，但只要还有后续文件就能继续翻页。无效、超限或被移除的草稿会提示失败；预览不会发布工具，也不会发送给模型。

如果编辑后的草稿与本会话已启用版本不同，预览分别显示两个摘要；没有自动升级或替换。要启用新版，先在会话插件清单撤回旧版，再重新预览和确认。

### 从预览直接启用

在没有同名运行版本、且工作区不是只读时，选择「在本会话启用」，核对确认页摘要后按「确认启用」。不需要配置模型，不会发起第二份 Agent 审批。宿主会从当前工作区重新读取草稿，摘要变化、会话切换或归档、应用退后台、权限变化都会使未提交的确认失效。失效后请重新预览，不自动重试；若提交先完成，以会话清单为准。该按钮只启用本会话试用，不安装或授予额外能力；重启后不会自动启用。

归档会话会撤回该会话的所有试用插件，同时作废其正在等待的插件变更。恢复会话不恢复插件；要再次启用，需重新申请批准。如果清理尚未确认，恢复会先重试清理。只撤回插件，不取消会话中其他已在运行的后台任务。

### 保存批准版本（不启用）

在草稿预览中选择「保存批准版本」，核对 SHA-256 后按「确认保存」。回到会话插件面板，打开「查看工作区已保存版本」，可读取校验结果。原始字节独立保存在应用私有存储里，编辑或移除草稿不会改动已保存的版本；进程重启后可重新校验，但不会自动启用。记录只在当前工作区可见，不是可导出包，也不是运行授权。

每个工作区最多 32 条记录，每个插件 ID 只保存一个版本：普通保存时，重复确认相同且完好的版本不会重复写入，摘要不同则拒绝覆盖。只读配置可以查看但不能变更。清单区分完整、损坏、不支持与查询失败。若保存结果未知，先刷新清单核对，不要直接重试。

### 从已保存版本启用当前会话

在「查看工作区已保存版本」找到校验通过的条目，选择「预览版本」，看清固定文本或变换行为与 SHA-256，再选择「在本会话启用」并确认。宿主会重新读取和校验**已保存的快照**，不会改用草稿；草稿已编辑或删除也不影响完整的快照。清单过期、快照损坏或格式不支持、工作区只读或前台确认失效，均不会启用。

启用不修改已保存版本，也不覆盖本会话正在运行的同名插件。撤回和会话归档只结束试用，不删除快照；重启后清单仍可查，但要重新确认才会启用。

### 替换或删除已保存版本

在校验通过的已保存版本预览里可以选择「删除保存版本」，核对摘要后确认。若工作区有一份校验通过且内容不同的同名草稿，预览会同时展示其工具行为，选择「替换保存版本」后再核对旧版和新版两个摘要。旧保存记录或新草稿在确认后发生变化时，宿主拒绝提交；同一份内容后来重新保存也不会复用旧确认。

删除和替换只改变工作区保存清单，**不会撤回或更新任何正在运行的会话插件**，也不会删除草稿和历史对话。旧快照不会自动保留，当前没有历史回滚；只读状态和损坏、不支持的记录不开放变更。结果未知时返回清单核对，不自动重试。

## 验证边界

- [源码编译测试](../../core/src/test/kotlin/com/cordiact/core/plugin/AuthoredPluginSourceTest.kt)验证严格版本、旧格式、摘要与尺寸；[运行时测试](../../core/src/test/kotlin/com/cordiact/core/plugin/AuthoredPluginRuntimeTest.kt)覆盖审批、下一轮调用、撤回、修改竞争、跨会话隔离、重启不激活、字面输入、Unicode 与结果上限。可信命令另见[作用域命令测试](../../interaction/src/test/kotlin/com/cordiact/interaction/ScopedInteractionCommandsTest.kt)。
- Android 侧请用 GitHub Actions 生成 APK，再在一条普通对话中走上面的流程。先拒绝一次，确认工具缺席；再批准，确认下一轮固定工具和变换工具可区分且都能调用；打开另一会话确认目录不泄漏；检查输出中的 `/`、`@`、`#` 未变成操作。回到首个会话，关闭模型连接后从会话插件面板确认撤回，再从草稿重新预览并确认启用。用只读配置重试应只可查看；预览之后切到后台再恢复，不应能提交旧确认。最后连回模型，验证下一轮只能看到当前启用的版本。再试用归档、恢复和补全中的 `/目标`、`/compact` 与 `/压缩`。另应保存批准版本、编辑或移除原草稿、重启并核对「已保存版本」摘要不变且会话工具未自动出现，再从保存清单预览并确认启用；验证模型下一轮返回的是保存快照的内容，而非改过的草稿。本机纯 JVM 不代替这项验收，且不在本机打包。
