# 工作区声明包：M1 验收

用同一次 Android CI 生成的 APK 和版本提交记录。以下是待执行的真机手册，不是通过报告。不要在非测试工作区或生产对话中操作。Android 测试分别覆盖 [Compose 导航入口](../../app/src/test/java/com/cordiact/app/experience/ui/ConversationSidebarTest.kt)、[预览确认](../../app/src/test/java/com/cordiact/app/experience/ui/WorkspacePackagePromptTest.kt)、[SQLite](../../app/src/test/java/com/cordiact/app/plugin/AndroidExtensionPackageStoreTest.kt)和 [真实 App 装配](../../app/src/test/java/com/cordiact/app/conversation/BundledConversationPluginCatalogTest.kt)。最后一项不调用外部模型；真机还要检查真正的前台对话和系统文件选择。

## APK 自动验收

Android Actions 的 API 29／35 仪器任务运行 [WorkspacePluginAcceptanceTest](../../app/src/androidTest/java/com/cordiact/app/plugin/WorkspacePluginAcceptanceTest.kt)。测试在临时 SQLite 中安装并启用 v14 扩展包，通过隔离进程实际执行工具、回合准入和工作流，再点击 Compose 组件菜单并验证草稿动作。切换工作区和停用插件后，验证组件撤回及旧注册失效。

在装有同次 Actions 应用 APK 和测试 APK 的 Android 设备上，可用 `adb shell am instrument -w -e class com.cordiact.app.plugin.WorkspacePluginAcceptanceTest com.cordiact.app.test/androidx.test.runner.AndroidJUnitRunner` 单独执行。系统文件选择、发布签名和升级保留按下面的手动验收记录。

## 样例

将以下纯文本保存为 `checkpoint.json`，放到系统文件选择器可选的本地目录。不要把私人数据写入样例。

```json
{
  "schemaVersion": 1,
  "id": "checkpoint",
  "version": "1.0.0",
  "title": "工作区验收",
  "description": "返回固定的测试文本",
  "host": {"api": 1, "minVersion": "0.1.0"},
  "capabilities": ["tool.publish", "command.publish"],
  "tools": [{"name": "message", "description": "读取工具测试文本", "kind": "static_text", "text": "PACKAGE_TOOL_OK_V1"}],
  "commands": [{"name": "package-checkpoint", "aliases": ["pkgcheck"], "description": "读取命令测试文本", "text": "PACKAGE_COMMAND_OK_V1"}]
}
```

## 通过条件

| 步骤 | 用户操作及预期 |
|---|---|
| 预览与取消 | 进入工作区 A，从「标签总览 → 设置 → 插件与连接 → 工作区插件包 → 导入 JSON」进入，也可在设置搜索「声明包」。系统选择取消不产生记录。选中样例可见版本、摘要、工具、命令和能力；关闭预览不安装。用无效/超限 JSON 验证不留记录。 |
| 分离安装与启用 | 确认安装后显示已安装、未启用；会话中不出现 `/package-checkpoint`、`/pkgcheck` 或工具。安装阶段不配置模型也可以完成。 |
| 实际调用 | 确认启用后显示运行中。选择测试模型，在普通前台会话调用 `extension.pkg.checkpoint.message`，核对工具轨迹实际返回 `PACKAGE_TOOL_OK_V1`（不要只依据模型文本）；另用未配置模型的环境输入裸 `/pkgcheck`，核对 `PACKAGE_COMMAND_OK_V1`；普通消息、非本地命令、带参数的命令和含附件草稿不能通过无模型入口。 |
| 作用域 | A 的另一个活跃用户会话可用；切换至工作区 B，不出现相同工具和命令。可以在 B 独立装一个相同 ID 的版本并启用；停用 A 不改变 B。 |
| 恢复与撤回 | App 进程重建后，只有首次进入显式启用过的工作区才恢复其包；其他工作区不会因启动 App 而恢复。停用 A 后，补全及下一轮工具列表不再提供贡献；重启后仍不恢复。已有对话不删除。 |
| 版本更换 | 修改样例版本为 `1.1.0`，将命令/工具输出改到 V2。运行时不能直接更换；停用并清理后，取消确认保留 V1。确认更换后先看到 V2 未启用；可回滚到 V1，回滚不启用且消耗回滚槽。 |
| 启动失败与重试 | 在 A 安装并启用另一个带相同命令别名的测试包后，尝试启用样例。样例显示启动失败，工具与命令都不可见；解除冲突不会自动启动，只有「重试启动 → 确认」才应用当前已批准版本。 |
| 权限 | 仅在测试工作区把配置改为只读。已运行包撤回，保留启用意图；只读不能安装和启用，仍可停用并清除意图。返回可写模式不把此前未启用包自动带起。 |
| Agent 转包 | 在工作区 A 的会话试用一个 Agent 编写插件并保存批准版本。插件页的「从已保存试用版本转包」展示原始摘要与新旧工具 ID；取消不写，确认生成 `0.0.1` 未启用记录。原试用与保存快照仍独立；B 不可看到 A 的快照。 |

## P0：同一 APK 接入两个独立声明包

用 [发布前检查](fixtures/extension-packages/release-preflight.json) 和 [会话交接](fixtures/extension-packages/session-notes.json) 验证。两个 JSON 不内置于 APK，不含账户、网络或可执行代码。样例避开受保护内置包的 `/release-checklist`，名称冲突不得覆盖。

| 步骤 | 通过标准 |
|---|---|
| 不改 APK | 在 A 依次从系统选择器导入两包。安装预览说明文案、动作和能力；确认安装后没有运行态说明页、会话动作或命令，显式启用才出现。 |
| 独立设置范围 | 聊天停在 A，设置切 B。B 不显示 A 的说明页或保存快照，不改变聊天、模型或草稿；只读访问 B 不会恢复已安装包。返回 A 后可读两页；停用或切走时，旧详情回到「插件与连接」。 |
| 只填入草稿 | 「标签总览 → 全部会话 → 当前会话行的会话操作」有内置「会话插件试用」和两包动作；其他会话行及归档行没有这些入口。点击一项只把对应裸主命令填入空草稿，不生成消息或请求。已有文本、附件或会话切换时不改草稿。未配置模型时，用户另点发送才显示固定文本。 |
| 撤回及不重放 | 停用其中一包，其说明页、动作和命令补全一起撤回，另一包不受影响。撤回后旧动作不填入，重新启用不复用旧注册。后台、旋转、离页后旧确认不执行；系统选择成功返回时，只在发起请求的范围内生成新预览。 |
| 布局与权限 | 竖屏顶部和横屏标签条无旧「插件管理」按钮。至少检查竖屏及横屏 `<950dp`、`≥950dp`、大字体、TalkBack 和 IME；试用检查器不盖标签栏或输入台，宿主审批仍可进入，关闭贡献不影响已有历史。 |

结果记录：提交号、CI run/工件、设备/API/构建类型、每项预期与实际、是否看到越界目录、失败发生阶段（存储/权限/运行/派发）、回退或阻断决定。不要记录模型密钥或私有工具输出。任何作用域或撤回失败均阻断放行。

## P1：只读插件诊断

| 场景 | 通过标准 |
|---|---|
| 安装与启用分开 | 进入「设置 → 插件与连接 → 插件诊断」。先安装未启用，再用管理页启用并手动刷新。诊断分别显示安装、启用意图和进程运行；不出现启停、探测、调用或导出控件。安装批准的贡献不标为当前授权。 |
| 选区与迟到结果 | 聊天停在 A，设置切 B 再切回 A。两个工作区安装同 ID 的不同版本。只显示当前 Settings 的版本；旧请求延迟返回不能恢复旧行，选区也不启动其他工作区的包。 |
| 内置和未覆盖 | 内置进程没有观测时显示「未观测」。会话试用、MCP 明示本页未读，不能当作「没有」或「已连接」。诊断不探测设备、远端或凭据。 |
| 空、旧库和不安全读取 | Android 存储测试验证缺库不建目录或数据库；已存在的空工作区显示未安装。旧版、坏库或需 WAL 副文件的库保留原样，报不可读而不是空清单。常规管理流程是否迁移由其自身处理。 |
| 签名目录观测 | 普通 APK 显示未配置；已配置 APK 在首次显式根刷新前显示目录未打开。后者分别检查打开未刷新、根快照、来源索引缺失/过期、已安装版本与摘要匹配或不匹配。安装来源仍是历史记录，匹配不是当前授权；刷新诊断只读取快照，不发请求、不创建或检查签名检查点、不改变租约和运行状态。 |
| 运行撤回与观测 | 用签名测试构建验证撤销、根换代与索引过期后，旧实例拒绝新调用，页面重读分别显示目录观测与进程最近状态；进程状态可以在后台清理推进后变化，不靠进入诊断触发。未配置发行源的 APK 只验「未配置」及本地流程，不记录签名联网验收通过。 |

## P1：工作台和工具结果

| 场景 | 通过标准 |
|---|---|
| 工作台标签 | 竖屏与横屏分别打开 Trace、Artifacts、Git Tree；切换会话时只显示其可用内容。检查横屏宽窄断点；撤回贡献后受影响的标签返回实际会话，不删除历史或产物，不影响其他标签。 |
| 工具结果与旧历史 | 用测试工作区生成受支持的成功结果，确认竖屏工具详情与横屏检查器呈现一致。查看旧记录、失败记录或没有匹配卡片的结果，仍显示通用详情；只看历史不会调用工具。标记敏感的受控测试参数或结果不出现在预览或复制内容中。 |
| 可替换搜索 | 只有配置测试凭据并主动点击测试时才发真实请求。在测试工作区依次验证两个已配置的 provider；工具和设置显式测试使用同一注册策略，设置「已注册」不能当成「已连通」。 |

## P1：导出后双工作区再导入

| 场景 | 通过标准 |
|---|---|
| 原始字节 | 在 A 安装 v1 或 v2 声明文件，在包卡片选「导出 JSON」；系统选择目标后，还必须确认精确版本和摘要。写入后独立读取文件比较 SHA-256 及字节；导入 B 仍要单独预览和批准，默认停用。A 的启用意图和回滚槽未变。 |
| 权限与取消 | 只读工作区不能打开保存器。工作区限制模式仅允许用户选定文档并明确确认的单次写入，不授予模型或插件任何文件权限。保存器取消、返回后再暂停、旧安装世代、页面重建均不复活确认。保存器可能已经创建空目标。 |
| 完成与不确定 | 用实际 SAF 写入授权、延迟或失败的文件提供方验证：提交写入时外部回执未返回不得返回到旧页面，旋转或重建后提示检查目标；不复写、不删除、不自动读回。写或关闭流异常时可能已有部分文件，不能报成功。 |
| 不支持格式 | 已保存试用转包和受保护内置包不作为普通声明 JSON 导出；快照审批、回滚、对话及内部 ID 不随文件发送。 |
