# CordiAct 开发能力验收场景

对应[长期路线图](../roadmap.md)。本表是验收规范，不是已实现用例或实测结果。现有 JVM 测试基线与未来产品验收的 12 个场景分开计数。

## 固定输入和判定

使用无秘密、fixture-only 的虚构项目；固定 Git 基线、文件内容摘要、仓库指令、预配置验证任务、伪模型输出与网络故障位置。先不调用真实模型或远端服务。每个测试独立创建 `project/workspace/session/run`，两项目的目录名可相同，但 ID、根、权限和运行账本不同。远端项目用专用临时 worktree，保留验证前后的基线和可比较的回执。

| ID | 阶段 | 场景 | 可机读通过条件 |
|---|---|---|---|
| R1 | M1 | 小项目按词和路径搜索，结果超过一页 | 排序可重复，分页无遗漏或重项；输出中的路径、行号可定位原文件。 |
| R2 | M1 | 从项目根到子目录加载冲突指令，含超预算输入 | 符合优先级、路径、信任和预算，报告被截断/跳过来源；不信任时不注入指令。 |
| R3 | M1 | 在最小任务中读取有边界的 UTF-8 行区间和显式技能 | 只读取活跃项目允许的文件；返回绑定到正确的文件版本和技能来源；超限有结构化响应。 |
| P1 | M1 | 一次审批提交一个已有文件的补丁 | 仅目标的一份文件改变；字节与预览的新版本相同；证据有旧/新修订和操作 ID。 |
| P2 | M1 | 预览后文件被外部或另一会话修改 | 同一旧预览返回 `STALE`，实际写入次数为 0，保留新文件；不能静默重算后使用旧审批。 |
| P3 | M2 | 两文件补丁和中途写入失败分别运行 | 正常时两个变更只出现在任务 worktree；失败时报告已发生的变更或 `UNKNOWN`，无无证据的全批成功或回滚声明。 |
| V1 | M2 | 以编辑后版本运行受控验证 preset | 回执绑定项目版本、preset、命令、退出码和持续时间；真实退出 0 且策略允许才标为通过。 |
| V2 | M2 | 验证非零退出、超时、未请求和丢回执 | 状态分别为 `FAILED`、`TIMEOUT`（只有收到执行确认时）、`NOT_RUN` 与 `UNKNOWN`；日志有界，均不显示通过。 |
| A1 | M1 | 取消、拒绝或错会话批准同一提案 | 文件写入/执行器调用为 0；查看原会话和切换会话不会改变批准的目标。 |
| A2 | M2–M3 | 项目 B 请求项目 A 的文件、远端会话或旧凭据 | 请求被拒且不激活目标会话；没有跨工作区记录或内容外泄；撤销后旧代的结果不重新发布。 |
| D1 | M2 | 提交后丢响应再断线，且宿主确实已写入或启动测试 | 对账后显示实际状态/未知；同一操作计数仍为 1；不会重发提交、批准或验证。 |
| D2 | M3 | 断线前后收到重复、缺口和旧代流，期间远端有待批请求 | 快照与有序日志能恢复可证实状态；不以不完整事件批准，旧答复失效；无副作用重复。 |

## 记录和发布门槛

每个场景记录 `fixtureVersion`、产品提交、宿主/上游提交、平台、可选模型/预算、预期与实测状态、操作计数和证据路径。记录只用合成内容、净化日志与必要标识，不导出真实私密文件、凭据或用户会话。

- `PASS` 代表判定实际运行并满足；用 `FAIL`、`NOT_RUN`、`UNKNOWN` 报告偏差，缺少日志不视作成功。记录还应注明本机 JVM、协议夹具、Android CI、真机四种证据类型。
- 发布分层：当前里程碑适用的硬门槛必须全过；全闭环目标的功能通过数至少 10/12，越权与重复副作用均为 0，所有声称运行过的验证都有机器可读回执。不得用高通过率抵消任一硬门槛失败或未知。
- 开启真实模型、跨机 TLS、后台/锁屏、系统杀进程等实验前，先用同一固定输入保存基线。耗时以同一场景、版本、预算的 p50/p95 比较；没有真机样本时不设拍脑袋的性能指标。
