# 固定来源的声明包分发（P1/M4）

## 已实现：离线核验

[核验器](../../core/src/main/kotlin/com/cordiact/core/plugin/SignedPackageCatalog.kt)只接收宿主提供的 P-256 公钥、固定 HTTPS 来源和互不重叠的包 ID 前缀。它不联网、不安装、不启用插件。真正的发布根、公钥轮换和服务地址还没有配置；测试使用自行生成的密钥及保留示例域名。核验通过不等于安装授权。

- 根签文件是严格 UTF-8 JSON，包含 `schema=1`、单调 `revision`、Unix 秒 `expires` 和完整 `grants`。每个 grant 含 `source`、`publisher`、`keyId` 及 Base64 SPKI `spki`。不继承旧授权；删除即撤销对后续制品核验的资格。单次接受时，过期时间不得距观察时间超过 30 天。
- 发布者签文件含 `schema=1`、本来源单调 `revision`、`trustRevision`、根原始 JSON 的 `trustSha256`、`expires`、`source`、`publisher`、`keyId` 和 `releases`。每个 release 只有 `id`、规范 `version` 和小写 `sha256`。索引不得晚于信任清单过期，单次接受时过期时间不得距观察时间超过 7 天。不接受 `latest`、版本范围或带前导零的版本别名。
- 使用 `SHA256withECDSA`、DER 签名。签名覆盖「ASCII 域名 + NUL 字节 + 完整 JSON 原字节」：根域为 `CordiAct trust catalog v1`，索引域为 `CordiAct release index v1`。不重新编码 JSON；未知字段、重复字段、重复版本或尾随内容拒绝。两个文档各至多 64 KiB，其下发的声明包至多 32 KiB。
- URL 从宿主固定来源路径与已验字段推导为 `packages/<id>/<version>.json`，不接受索引传任何 URL。制品按原始字节校验 SHA-256，独立编译宿主声明并逐字验证包 ID 和版本。选择和待确认候选绑定索引与信任清单的当代对象；更新、撤销或过期后旧候选不得通过提交复核。
- [私有检查点](../../core/src/main/kotlin/com/cordiact/core/plugin/SignedCatalogCheckpoint.kt)可跨正常重启保留根和各来源已验的最高代数、原文摘要及最后成功持久的 Unix 秒时间高水位。单一事务在独立锁文件和完整记录比较下原子替换；写入失败、旧实例或未知结果不沿用旧授权。过期、撤销或重启不抹去门槛。重新打开后没有可选目录，须重新提供有效的签名原文；检查点只用于**拒绝回退**，不是可直接恢复授权的签名缓存。
- 检查点绑定固定根指纹及来源配置。仅受信宿主可在已准备的私有路径显式初始化；普通打开遇到缺失、损坏或配置不匹配即关闭，不能静默重建。完整文件校验和只检测意外损坏；在没有独立可信锚时，不能防止整盘回滚、删除全部文件或恶意重写，也不保证离线实时撤销。[测试](../../core/src/test/kotlin/com/cordiact/core/plugin/SignedPackageCatalogTest.kt)覆盖两个来源、篡改、错误签发者、超出命名空间、精确匹配、回放、期限、撤销和跨实例拒绝旧候选。

## 已实现：固定制品的受限下载

[下载适配器](../../core/src/main/kotlin/com/cordiact/core/plugin/SignedPackageDownload.kt)只接收当前已验签索引中的精确选择。准备阶段不联网；执行同一操作最多一次，在发送 HTTP 前及收到制品后复核原宿主作用域与索引。撤销、过期、摘要错误或离开原作用域会丢弃结果。宿主必须用原页面、工作区、前台和策略身份提供回调；不能只比较当前工作区名称。退出时可显式取消，已发生的网络访问无法撤回。它不获取根或索引，也不安装、启用或自动重试。

- 专用 OkHttp 客户端保持平台 TLS 验证，禁用 HTTP 代理、Cookie、认证、缓存和重定向；不发送正文或工作区、会话、账号等信息。非 200 在首个 HTTP 交换内拒绝，另设一次性发送门闩。网络仍可能看到域名、来源 IP 和请求的包 ID／版本；不绕过系统 VPN 或 DNS。
- 仅接收不压缩、具单一有效 `Content-Length` 或完整 chunked framing 的 200 响应；拒绝空、截断、冲突头及超过 32 KiB。限额约束应用正文，不是网络线路字节预算。15 秒覆盖传输，不包括宿主排队和确认，不承诺能立即终止阻塞的系统 DNS。成功后按原字节重新校验摘要、ID 和版本。
- JVM 以回环 TLS 实测实际报文与拒绝路径，未访问真实发行端点。Android 已接条件入口，尚未验证 APK 对应依赖变体及 API 26 的 TLS 与取消行为。

## 已实现：同一安装确认与来源收据

[工作区安装服务](../../core/src/main/kotlin/com/cordiact/core/plugin/WorkspaceExtensionPackages.kt)在下载前绑定原页面、工作区、权限和前台世代。取得核验候选后仍须人工确认，走原有[安装器](../../core/src/main/kotlin/com/cordiact/core/plugin/ExtensionPackageInstaller.kt)的同一 CAS；最终提交重新验证原证据。安装与升级不启动实例，收据也不授予任何贡献权限。

[Android 包库 v3](../../app/src/main/java/com/cordiact/app/plugin/AndroidExtensionPackageStore.kt)在同一事务保存当前与回滚制品的来源、发布者、签发键和核验代数。普通打开可迁移 v1/v2，不补造来源或更改原包字节；诊断只读打开不迁移，并将收据明确显示为安装历史，不是当前信任。受控前缀不能经普通 JSON 或已保存试用冒用；不同来源或发布者不能覆盖已安装版本，受控制品不能裸导出。新启用、重试和回滚要求当前签名索引仍有相同所有者和精确制品；停用和移除不依赖来源在线。签名包不随工作区首次进入或进程重建自动恢复，启用意图保留供用户显式启动。

## 已实现：独立的显式目录刷新

[刷新服务](../../core/src/main/kotlin/com/cordiact/core/plugin/SignedCatalogRefresh.kt)经固定来源的 `catalog/trust.cdx` 刷新信任根签文档，再由用户对已获授权的来源和签发键显式访问其 `catalog/indexes/<keyId>.cdx`。两个动作都是一次性 GET，不自动串联或回退换源；根成功即独立发布，后续索引不存在、坏签或不兼容不能恢复旧信任。根与索引均采用一个二进制帧：ASCII `CDX1`、大端 4 字节 JSON 长度、2 字节 DER 签名长度，随后精确的原始 JSON 与签名字节；不接受尾随内容，正文最多 64 KiB、签名最多 72 字节。HTTP 仍遵守制品下载使用的隔离策略。

索引请求在发起时绑定根对象及该来源的索引世代；迟到结果不能借另一个世代重新发布，签名正文也必须绑定根的代数和摘要。刷新不执行安装或运行，不在网络 I/O 中持宿主和目录锁；最终发布由原工作区页面、权限、前台身份和检查点共同确认。过期拒绝只保留观察到的时间门槛，不推进拒绝文档的代数。取消在最终发布准入前有效，不能撤销已经发送的请求或已进入提交的本地操作。

## 已实现：运行租约与撤回

签名包显式启动时取得绑定**精确根和来源索引世代**的进程租约；同文档幂等重验不影响租约，其他来源的索引更新不影响本来源。新的根或本来源索引一旦发布，旧租约立即失效，即使新索引仍包含相同制品；到期、已发现检查点不一致也会关门。工具、命令、会话动作及设置说明的实时查询共享同一门槛，热路径不访问磁盘或网络。下一次背景清扫撤回整批失效实例，再调用清理；已在屏幕上绘制的内容要等重新投影。清理失败保留待清理状态，不重新开放。目录更新和清扫不修改安装记录或启用意图，不自动以新租约重启，也不能撤销先前已开始的动作或外部副作用。

正常单宿主中同进程目录发布即时生效；已运行签名实例存在时，宿主周期检查本地检查点、时间和清理，无网络请求。其他实例/进程修改检查点只在被探测后停止旧租约，不是实时跨进程撤回。进程重建后即使有有效索引，签名包仍须用户显式启动；普通本地包沿用原恢复行为。

## Android 装配

受信构建可在 APK 根资产中打包 `cordiact-signed-catalog-v1.txt` 预配置目录。普通构建从空目录状态启动。工作区插件页对每个已批准目录使用同一[签名目录面板](../../app/src/main/java/com/cordiact/app/experience/SignedPackageDirectoryPanel.kt)。用户分别刷新根和索引，选择精确版本下载并预览，再用已有批准界面确认。离页或进入后台撤回旧作用域并取消仍在传输的请求。

[资产规范与私有路径装配](../../app/src/main/java/com/cordiact/app/plugin/AndroidSignedCatalogAccess.kt)：最多 4 KiB，ASCII、LF 分隔、无注释；首行 `CordiAct catalog policy v1`，再依次为 P-256 公钥 SPKI 的标准 Base64、十进制最低根代数、该代根 JSON 原字节的 64 位小写 SHA-256、用于根文档的固定来源 ID，随后每行 `<来源ID> <HTTPS目录URL/> <保留包名前缀->`。不打包私钥或账号凭据。命名空间在首次联网前即保留；资产存在但无效则不开放网络，也不把未知保留名称视作本地可用。只在第一次显式根刷新时打开 App 私有 `no_backup` 下的固定检查点；初次创建目录时使用 APK 最低根门槛，已有目录而状态缺失或损坏时不自动初始化。检查点不恢复活动索引，整目录删除或整盘回滚无独立可信锚，不能宣称有防护。

SDK 的 `cordiact-catalog` 可生成 APK 公共策略、根签文档、精确版本索引及对应制品。Beta 工作流可通过仓库变量 `CORDIACT_BETA_CATALOG_POLICY_BASE64` 配置公共策略。独立根管理员与发布者的操作见[SDK 签发文档](../../plugin-sdk/README.md#签发与发布)。

### 客户端自管目录

用户从工作区插件页用系统选择器导入同格式的公共策略。预览显示根公钥 SHA-256、最低根代数、HTTPS 来源和保留前缀，确认后把策略写入设备私有存储。确认受原页面、工作区权限和前台世代约束。自管信任配置作用于当前设备的所有工作区，包安装、权限和启用仍各自按工作区确认。导入不联网，首次点击刷新才打开对应检查点并访问根来源。

APK 和自管目录使用独立检查点。拒绝与 APK、自管目录或现有无签名安装冲突的命名空间。停用目录会撤回仍在进程中的验签证据和运行租约，保留安装记录、保留前缀和检查点。用原策略文件重新批准可恢复该目录，之后需要重新刷新和启用。最多记录八份自管根策略，包含已停用项。更换根公钥或改变保留前缀需要单独的数据迁移。

## 只读诊断：进程观测不授予信任

设置的插件诊断区分 APK 未配置、策略无效、目录未打开、根未刷新、过期、失效及已观测状态。对含签名收据的当前安装版本，额外显示发布者、索引及精确制品与当前进程快照的匹配状态；历史安装来源与进程最近运行状态分别展示。刷新诊断不打开签名目录、检查检查点、刷新网络或推进租约时间水位；公钥签名验证、安装及运行授权仍在各自操作入口执行。

## 生产发行前的必要条件

1. **发行配置。** 确认真实双来源、公钥轮换和撤销职责。需要提高 APK 基线、换根或修改来源时，设计可验证的迁移，不把旧检查点替换为新空文件。没有可信发布端点和配置前不开放生产分发。
2. **Android 验收。** 对已配置的同一个 APK 测试提交落盘、真实端点帧协议、取消、迟到结果及签名失效。不自动恢复活动缓存；若将来缓存签名原文，仍须逐字重验签名并对照检查点。
3. **生产运行验收。** 在 Android 用受信宿主固定前缀启用目录配置，并验证离线有效期、撤回、清扫和过期提示；历史收据或本地诊断不是实时信任。验证晚到结果、过期和写入失败不会导致无签名降级。
4. **诊断与验收。** 诊断只读最近已验证快照和固定状态码，不刷新网络，不启动插件。用两个实际签发来源验收升级、撤销、重启保持来源和 Android API 26+ 的签名验算；网络替身记录应验证无重定向、无第二次请求、无授权或凭据泄漏，文件或目录损坏不会静默清空记录。生产请求与受控源安装在这些条件具备前不开放。
