# CordiAct「一切皆插件」能力追平计划书

**状态：立项建议，非已交付承诺。** 对标口径：工作区 CordiAct `89fda8d` 与 DeepSeek Harness `d98f5d6851` 源码快照，不把当前运行的 DSH Web 或其他版本当作同一基线。本计划基于源码与既有验证记录，本次未新增运行测试。

## 1. 项目目标和交付口径

CordiAct 不缺「插件」这个概念，也不缺插件内核。当前缺口是：用户创作、APK 内置能力、声明包和 MCP 走不同管理路径；工具和命令之外的客户端与 Agent 能力，还没有同样清楚的贡献、组合与卸载约定。应先把已有能力变成同一套可管理的产品，再拓宽扩展面。

这里的「一切皆插件」指**业务能力通过接口注册、由配置组合、有明确归属、可观察、可撤回，并在适用时可替换**。不是所有代码都要可卸载。最小宿主保留启动、信任判定、审批和 Android 权限、工作区与会话身份、生命周期与恢复、持久化事务，以及最终执行准入。会话基本可读性、权限界面和安全模式不能受第三方插件启停影响。必备业务能力可以是受保护系统插件；保护身份由宿主决定，外部包不得自报。外置 Node 插件在 Harness 上运行，不宣称能在手机离线执行。

| 里程碑 | 用户能做什么 | 对标边界 |
|---|---|---|
| A · 管理闭环 | 不写代码、不选模型，即可预览、安装、启停、配置、升级、回滚和诊断本地声明包；Agent 可创作并申请精确版本，人可以拒绝或撤回。 | 本地管理体验追平，不含广义扩展面。 |
| B · 本地可组合 | 工作区可选配置方案；同一个包发布工具、命令、设置或 UI 卡片；宿主可替换示范 provider 和会话策略；卸载不破坏历史。 | 在本计划签字确认的扩展点上达到 Android 等价，不把每个 DSH 包、每个 Web slot 算作必做。 |
| C · 生态可接入 | 可浏览签名索引、选择精确版本；可连接固定版 Harness，看到来源明确的远端能力和会话投影。 | 区分本地原生、协议互通、仅远端可用；更宽的远端写操作是后续范围，不以只读接入宣称完整生态兼容。 |

## 3. 目标架构与关键约定

**统一控制面，不强造统一执行引擎。** 沿用 [Android 原生优先 ADR](../adr/0001-android-dsh-runtime-boundaries.md#L19-L39)，由 `Plugin Manager` 管理描述、安装、配置、选用和诊断。运行适配分为：APK 随包的可信 Kotlin、宿主解释的声明包、HTTP MCP 连接、外部 Harness 对接。可移植 Cordis JS 作为独立决策项，不是前三个里程碑的依赖。不同来源共享清单和诊断，不必共享原始包格式、凭据或数据库。

| 契约 | 做法 |
|---|---|
| 身份与组合 | 包身份包含发布者/来源、包 ID、版本、摘要；实例包含包身份引用、目标、作用域、世代。配置方案映射到选用与配置，不引入第四套授权作用域。先按「受保护默认配置 → 工作区选用 → 会话显式试用」解析；同一作用域的冲突明确报错，不隐式依赖安装顺序。子 Agent、后台任务默认不继承前台目录或审批。 |
| 安装与运行 | 安装记录（字节与来源）、使用意图、实际运行状态和授权分开建模。验证与入库不发布贡献；启动在提交点一次性发布贡献组。升级先校验候选、显示差异并取得新增能力同意，再切换；切换失败按上一个可运行版本尝试恢复，若恢复失败显示故障，不假报在线。单槽回滚不等于数据迁移可逆，不可逆迁移不得进入自动切换。 |
| 撤回与恢复 | 停用先关闭新调用准入，再撤注册、取消并清理本世代资源。下一轮重新投影，旧回合不能借同名、同 schema 或相同摘要进入新世代。外部副作用不会被自动撤销；提交或远端动作结果未知时先对账，不重放。清理未完可以重试，不视为已完成停用；安全模式仅启用必备系统能力。 |
| 贡献接口 | 以服务定义、provider、消费者三方验收替换点。先发布工具、命令、配置表单和受限 UI 描述；可信插件才可注册可执行回调。对扩展回调定义类型、顺序、时限、取消和故障降级；模型所见增量随会话记录，旧会话在插件缺失时仍可读，不为回放重新执行插件。 |
| 授权 | 安装预览说明来源、作用域、将公开的能力及数据去向。安装/启用同意、单次操作审批、Android 原生权限分别核验。授权绑定来源/摘要、作用域、能力集合及世代需要的当前身份；进入执行器前复核。密钥用宿主保管的引用，不能出现在清单、日志、模型输入或远端同步中。 |
| 对外兼容 | 为宿主 API、清单 schema、贡献类型及远端协议分别建立版本策略。未知/不支持能力明确拒绝，不用静默降级掩盖权限差异。发布兼容矩阵标注「本地原生 / 受限声明 / 仅远端 / 不支持」。 |

**迁移策略。** 先接读模型、再接事务写路径、最后替换旧入口；每类记录只有一个写入所有者。继续读取旧批准快照，旧记录不自动安装或恢复运行；用户可以显式迁移并预览新旧工具 ID，保留原摘要来源，不为旧标识创建调用别名。同一份现有 MCP 配置先接投影、后切连接治理，凭据引用原地复用。已有系统能力先用适配器挂入目录，不同时重写其实现和权限规则。

## 4. 排期、责任与退出条件

**估算前提：** 1 名 Android/Compose、1 名核心/协议工程师，QA 与安全评审各兼职；并行仅限独立任务，按累计 12–15 周估算，不是日历承诺。若只有一名工程师，优先交付 A 和 B 的首条切片，C 另排。阶段完成以退出条件为准。

**首个开发切片。** 用现有内置示例的工具与命令行为制作一个独立 ID 的本地用户包；在真实 APK 打通「预览 → 安装不运行 → 工作区启用 → 会话补全和下一轮实际调用 → 关闭后一并撤回」。宿主按已验证的执行器识别 `PURE`，不按包自报或名称前缀放行。用「另一工作区默认不可见、同时启用后停一个不影响另一个、旧审批不能进入新代」验收。M3 另复核[凭据更新](../../app/src/main/java/com/cordiact/app/experience/settings/AndroidMcpSettings.kt#L85-L107)与[审计白名单](../../core/src/main/kotlin/com/cordiact/core/settings/SettingsOperationAudit.kt#L7-L21)，修复时不绕过审计，并补轮换失败保留原凭据和连接的测试。

**实施检查点 1。** 已将声明工具的效果与宿主生成的注册世代绑定，并移除声明命令对跨实例共享开关的依赖。纯 JVM 六模块测试 1072 项通过（0 失败、0 跳过），尚未执行 Android CI 或真机流程。已确认首版入口：**从当前工作区进入独立「插件」页**，管理该工作区已安装包；现有会话面板继续承载临时试用。安装不自动运行、跨工作区独立、会话试用不恢复。本轮未改布局、存储或导航。下一步先接工作区存储与安装事务，再接已确认的入口。

**实施检查点 2。** 工作区安装事务已按预览原字节与安装世代比较写入，保留一个回滚槽；新增 Android 私有 SQLite 适配及重开、并发、损坏保护测试。纯 JVM 六模块 1075 项通过（0 失败、0 跳过）；尚未接入 App 管理服务或页面，Android 测试待 CI。首版主导入方式已确认：**在工作区「插件」页用 Android 系统文件选择器选取一个本地 JSON**，预览版本及能力后才可安装；不申请全盘文件访问，不扫描工作区目录。后续的 Agent 试用转包仍走同一安装确认流程，不作为首版的第二个文件导入入口。

**A–C 之后的扩展。** C 达成只代表管理与选定扩展体验追平，不代表 DSH 插件逐包兼容。若项目要继续追平更广生态，按用户需求选一组真实 bundle，逐包标注「需适配 / 仅远端 / 不支持」与缺失的服务、UI 或权限；先补通用接口，避免按包特判。随后分开评审三项：① 远端受限写操作和启停（独立授权、取消和对账通过才开放）；② 更多 provider、会话投影、工具及回合钩子（已有两个独立消费者再稳定接口）；③ 仅在真实用例与安全评估支持时，提供受限可移植 Cordis 运行时。逐项另行估算，不纳入 12–15 周。

**实施检查点 3。** 当前工作区侧栏更多菜单已接入独立「插件」页。系统选择文件后限量读取并预览，确认绑定页面、权限、原字节和安装世代；提交前失去前台或退出页面时拒绝。页面能安装、更换、回滚和移除记录，不发布贡献。纯 JVM 六模块 1079 项（0 失败、0 跳过）；Android 页面、存储和系统选择器仍需 CI/真机。下一步是用户包启停。已确认恢复策略：**App 进程重建后，在首次进入对应工作区时恢复用户显式启用的包**；恢复要求安装世代仍匹配、当前权限仍有效。安装不自动启用，会话试用仍不恢复。

**P1 · 本地分享与受控分发。** 普通声明包支持经系统保存器导出精确已安装版本的原始 JSON。返回前台后需再确认，只传原文件字节，不附带安装同意、启用状态或回滚；目标写入未确认不重放。分发已有[离线签名核验层](signed-package-distribution.md)，可验证不同来源的固定版本和摘要，拒过期、撤销和同代内容冲突。新增私有检查点，使正常重启保留已验代数和时间门槛；重开仍需重验签名，不能靠门槛恢复授权。已加精确制品的一次性 HTTPS 下载并用回环 TLS 验证，不提供任意 URL，也不会自动获取索引。已验候选复用同一安装确认和 SQLite CAS，当前与回滚版保存历史来源，裸本地导入不能冒用配置保留的包名。已有独立的根和单来源索引显式刷新、固定端点及严格签名帧。索引绑定原根世代，刷新不会安装或启用包。Android 已接可选签名目录面板和 APK 信任策略；默认无可信来源时不显示、不联网，尚未配置真实发行源，不宣称已开放签名分发。签名包运行租约绑定精确根与索引世代，失效立即拒绝新调用，后台清理且不自动续租；Android 实机验收待完成。

**P0/P1 · 真机检查点。** [PR #92](https://github.com/wuyhong715/CordiAct/pull/92) 的 `623ee44` 对应 [Android CI 第 2 次尝试](https://github.com/wuyhong715/CordiAct/actions/runs/45334743450/attempts/2) 和 [Debug APK 工件](https://github.com/wuyhong715/CordiAct/actions/runs/45334743450/artifacts/14893009027)。Android Debug 单测 265 项、JVM 1,181 项通过；用户于 2026-11-24 确认实机测试通过，未提供设备型号或逐项记录。该普通 APK 不含签名发行配置，不把此次确认扩展为生产签名分发验收。P2 在独立分支继续，不改本候选。

**P2 · MCP 发布世代。** [MCP 工具桥](../../mcp-client/src/main/kotlin/com/cordiact/mcp/client/McpToolBridge.kt)将执行器和可见性回调绑定到原发布世代与原连接。同名重发（包括复用连接对象）不会让旧执行器转发新调用；宿主注册表先验证整批工具及作用域冲突，再一次提交定义和可见性规则，不暴露部分注册。撤回先关准入，只凭原注册句柄清理；即使清理失败后同 ID 已被其他所有者重建，重试也不会移除替代定义或其可见性规则。按回合投影还核对候选注册与可见性规则的原身份；规则在锁外执行，检查期间若注册或规则被替换，丢弃结果，不借用新规则。诊断不把待清理项当成已发布。已经派发的远端动作不承诺撤销；若结果晚于世代撤回，则不交付旧结果，也不自动重放。本切片不把暂时请求失败等同于断线，也未实现自动重连或目录统一诊断。

**P2 · DSH 只读跟随首切片。** [固定版兼容性与模型](dsh-readonly-session-follow.md)已核对到 `dsh-v0.2.3-alpha.1`。默认认证是 owner，不能充当只读主体；已实现不联网的最小状态投影，按连接、本地工作区、会话和打开世代隔离，断线或撤权清空，旧响应不可恢复。不开放清单、历史、远程写入或 Android 连接入口。

**P2 · Host 插件切片。** [只读 Host 插件](../../deepseek-harness/host-follow/README.md)加入一次性、单目标、短时进程内授权，从已加载的真实 DSH 注册目录只采三个字段，撤权和卸载关闭现有流。核心与继承管道共 16 项 Node 回归通过；真实 Loader 既验证了固定提交重建 Cordis 的混合工件，也验证了同树正式构建。独立 Node TLS 载体只绑定回环临时端口，已与 Kotlin 互操作，并在同树正式 CLI 的合成 profile 内验证真实 Loader 的卸载撤回；未装入默认 DSH profile，没有外网入口或 APK 接线。

**移动端参考。** [DSH Go v1.3.0 对照](../research/0014-dsh-go-mobile-plugin-reference.md)支持把载体与原生投影分开、按当前 Host 和协议决定显示能力，而不是把所有 DSH Web 插件入口搬进 Android。CordiAct 保留 Compose 宿主和独立只读授权；不接入 DSH Go 运行时、宽权限桥或网页岛。固定版正式构建与混合验证保持独立。

## 5. 验收与发布门槛

- **功能闭环：** 以 D1–D7 的范围内条目为分母，每项须标注「本地 / 等价 / 仅远端 / 延后」以及相应 PR、CI 工件与设备证据。方案评审先冻结范围；不能用插件数量百分比代替验收。
- **作用域与撤回：** 两工作区 × 各两会话；清单、命令补全、模型工具 schema、直接执行都做负向测试。覆盖启动失败半注册、旧世代、等待审批时撤回、依赖失效、清理重试、撤回后晚到结果丢弃。越权进入执行器与跨作用域泄漏均须为 0。
- **数据与故障：** 安装不激活；进程杀死后仅按持久意图和仍有效授权恢复允许重建的实例，试用不恢复。对存储提交间隙、版本不兼容、配置迁移失败、凭据失效和远端断线注入故障。保留基线和兼容性报告，不因目录打不开而清空配置；未知结果按操作 ID/实际状态对账。
- **可用性和性能：** 至少用基准 Android 真机及现有 CI 支持的 API 矩阵验证；用同一 release 构建与同一设备对照。有 20 个已安装但未启用的样例包时，建议目标为冷启动 p95 增幅 ≤10%，插件列表首屏 p95 ≤500 ms（本地、索引已建）；停用返回后不允许新调用进入。M0 采样确认预算和设备，不能只用 JVM 结果宣布移动端达标。
- **证据与回退：** JVM 验证解析、生命周期与权限；Android UI/存储测试验证真正入口及进程重建；关键链路跑真实组装和真机；协议用固定 DSH 版本验证。按工作区分批试点，发布前演练关闭新扩展入口与只启动系统插件的安全模式。回退保留安装记录、配置和历史，不能靠删库修复。

## 6. 主要风险与需拍板的决定

| 风险 | 控制与负责人 |
|---|---|
| 系统能力改造波及登录、对话或安全入口 | 先适配注册，不动最终准入与最小历史读取；由核心负责人审核每条从系统代码迁移出的能力是否真可替换。 |
| Android 后台/进程死亡导致错误恢复，或 UI 显示与实际不符 | Android 负责人用事务和进程重建测试区分安装、意图和运行；默认无自动恢复会话试用。 |
| MCP/远端数据越界，或连通即被误认为可调用 | 协议负责人给本地与远端单独建身份、授权、世代；只读首发，以兼容测试证明受限主体；写操作另立项目。 |
| 供应链与本地脚本超出移动端可控范围 | 外部默认仅声明式；隔离进程固定脚本 PoC 已有[历史设备证据](../testing/sandbox-s3-js-engine-and-poc.md#L68-L83)，不代表第三方运行时可上线。只有签名、资源约束、隔离与权限验证、真机证据和渠道政策均通过，才讨论受限随包 JS；不阻塞 A–C。 |

**建议批准：** 先立项 M0–M1，锁定「用户可自行安装且能可靠撤回声明包」作为第一发布目标；同时确认工作区配置方案粒度、两个示范包及固定 Harness 版本。M1 通过真机验收后，再批准后续扩展与远端范围。暂不承诺 APK 内任意代码、完整 DSH Web 客户端兼容、公网市场或全量离线 Harness。
