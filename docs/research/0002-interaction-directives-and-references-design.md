# 交互集成插件：指令语法与授权设计

**状态：** 设计已落地首期实现，Android UI/主工程编译待 CI 验证
**日期：** 2026-11-01
**范围：** 定义 CordiAct 客户端交互集成入口的 `/` 行为指令、`@` 提及、`#` 填充、语法校验、辅助与授权边界；本轮已按此设计落地可测契约、Android 接线与基础 composer。

## 1. 设计结论

交互集成插件是客户端能力的受管集成入口，不拥有所有业务能力。它组合普通模型输入、命令目录、实体目录、Workspace/Session 上下文与受控分发；具体命令、可引用实体和可调用能力仍由各自功能插件注册并实现。

输入有三种不同含义：

- `/`：选择一个已注册的行为，并将其作为受管命令/自动化执行。未使用 `/` 时，只是普通模型请求，不得由自然语言推断出系统自动化、后台任务跟踪或隐式授权。
- `@`：明确引用一个实体，并为本次请求引入对该实体的范围化访问意图。实体必须被解析为真实、唯一且当前可访问的对象；正文中的相同专有名词不等于引用。
- `#`：在发送前用用户本地预设值替换已知填充键。替换只在客户端本地完成，不是模型工具或服务器端命令。

三种语法各司其职：`/` 决定执行路径，`@` 决定对象及授权范围，`#` 决定文本值。任一项都不能覆盖插件能力门禁、Workspace/Session 隔离、平台权限或高风险操作确认。

## 2. Harness 参考与 CordiAct 边界

DeepSeek Harness 值得沿用的主要模式是：命令由插件注册，客户端命令目录负责发现和解析；未知 slash 命令不能静默降级成普通 prompt；composer 内的资源引用保留结构化身份，不靠模型从标签猜对象；模型选择和具体业务能力仍属于独立功能包。

CordiAct 的交互分发还必须遵守现有 Workspace-first 约束：会话始终属于持久化 Workspace，provider 不能选择或重定义 Workspace。当前已有 `ModelAdapterService`、插件生命周期、Workspace/File/Tool Manager、`ActionPolicy` 等边界，但没有完整 Android composer，也没有通用自动化任务编排器。因此下文的 `CommandRegistry`、`MentionResolver`、`AutomationTaskController` 是需要后续设计/实现的接口角色，不代表它们现已存在。

## 3. 语法模型

### 3.1 行为指令 `/`

行为指令只在输入首字符处生效；首字符前不允许隐式 trim 后再激活，以免复制文本被意外变成命令。普通正文中的 `/` 是普通字符。

规范形式：

```text
/<完整注册命令><分隔符><行为正文>
```

- `<完整注册命令>` 必须精确命中命令目录中的一个完整主名或已注册别名。允许按注册规则做大小写/Unicode 规范化，但不得前缀匹配、模糊匹配或由模型临时创造命令。
- `<分隔符>` 为全角冒号 `：` 或一个以上空格。Tab、换行是否作为分隔符不纳入首期语法；建议拒绝并给出修正提示。命令名和分隔符之间不允许插入空格，避免解析出歧义。
- `<行为正文>` 可为空仅当该命令 descriptor 明确声明允许空正文；否则发送前语法错误。
- 同一份草稿只允许一个首部行为命令。正文中再次出现 `/` 不启动嵌套命令，除非后续注册的命令正文 grammar 明确提供结构化子命令。
- 未注册的 `/xxx`、命令部分输入、缺少分隔符、重复行为头或未授权命令都是显式错误；绝不退化成普通模型消息。

例如：

```text
/目标：依据@产品工作区：自动化设计案执行任务
/总结 整理@产品工作区：发布记录
```

命令目录由插件注册 `CommandDescriptor`：稳定命令 ID、输入名/别名、展示名与说明、参数/正文 grammar、需要的能力、允许的受体类型、执行模式、取消策略、生命周期/审计策略。名称重复时注册失败；插件禁用、卸载或失去能力时，命令即时不可执行。

### 3.2 提及指令 `@`

`@` 不是任意字符串查询，也不是访问任意本机路径的通配符。它启动实体选择，选定后在草稿中保存稳定实体 ID、类型、所属范围和显示标签。可引用实体由受信目录提供，例如：子 agent、Workspace、项目、Workspace 内目录/文件、skill、MCP server、插件及后续扩展类型。

提及层级首期限制为最多两级：

```text
@<一级受体>
@<一级受体>：<该受体所包含/授权的二级受体>
```

二级关系必须由实体类型的父子关系规则声明，不能把任意两个实体拼成一条授权链。示例 `@产品工作区：自动化设计案` 表示先选中产品工作区，再从其允许的子实体中选中设计案；不是字符串路径拼接，也不代表该设计案一定是文件，最终类型取决于 resolver 返回的实体。

受体插入应优先使用编辑器结构化 chip/token，显示人类可读名称、类型图标和失效状态，内部持有不可由用户标签伪造的稳定 ID。复制/导出到纯文本时使用无歧义的序列化形式；重新粘贴需要重新解析并重新校验。不能仅凭 `@产品工作区` 这段普通文本就推断权限。纯文本中手工键入的提及只有在实体目录中精确唯一命中、类型符合当前位置、父子关系合法且授权检查通过后才可转为有效 token。

`@` 覆盖的是显式选择的对象，不扩大到整个磁盘、所有 Workspace、同名实体或插件内部私有存储。文件系统实体必须由 Workspace File Manager 解析为 Workspace 相对路径；拒绝绝对路径、路径穿越、越界符号链接、被归档 Workspace、已失效 URI 和不具备能力的插件。

### 3.3 指代词

代词只可指向本条输入内已经明确提及、且当前仍有效的受体；代词本身不创建新授权，也不能把访问扩展到另一个对象。首期建议支持显式指代 token（例如编辑器由“引用上一个受体”辅助项插入的 `它`/`该文件` chip），并允许识别 `它`、`该文件`、`该工作区`、`前者`、`后者`等自然语言文本作为待解析指代。

- 唯一前项且类型兼容：解析为该稳定实体 ID，蓝色。
- 多个可匹配前项、无前项、实体已失效或类型不兼容：标红，发送阻止；用户可通过补充 `@` 或从指代候选菜单重绑定。
- 跨消息指代首期不自动推断；未来若提供“引用上一轮对象”，必须在 UI 中显式呈现其来源，并重新校验当前 session/Workspace 与授权状态。

这样既可支持“依据@工作区：设计案执行，并修改它”，也不会让无来源的“它”被模型自由解释成任意文件。

### 3.4 填充指令 `#`

用户可预先设置本地填充值，例如 `#111 = 123456789`。在发送动作发生时，客户端只替换完整、已定义的键 token：

```text
原草稿：订单号 #111
发送文本：订单号 123456789
```

键名按完整 token 匹配，不做子串替换、递归展开或模型侧展开。未定义键、格式错误或同名冲突时标红并阻止发送；用户可通过“插入填充值”菜单选择键，查看值的遮蔽预览，并在发送前检查最终展开文本。定义、改名、删除均由用户主动完成；值保存在应用私有存储，不放入普通偏好或日志。填充值不是密钥保险箱，不应承担 API key/认证凭据管理。

编辑器应区分未展开原稿与实际发送文本；对话历史显示用户实际发送的展开结果，避免记录中看不到模型收到的内容。可选地保存非敏感的键名/展开标注用于本地编辑回显，但不得为复现而在日志重复记录值。用户须知：填充值会作为普通消息内容发给模型并可能进入会话持久化；敏感凭据不得放入此机制。

## 4. 发送管线与行为结束

发送前按固定次序处理，任何阶段失败都不发模型请求或执行命令：

1. 获取不可变草稿快照及当前 Session/Workspace ID。
2. 解析首部 `/`；若存在，精确解析完整注册命令和正文分隔符，验证插件状态、命令输入 grammar 与执行权限。
3. 解析所有 `@` token，绑定稳定实体 ID，检查层级/父子关系、当前 session/workspace、实体新鲜度和授权范围。
4. 解析指代，绑定至同草稿中唯一且兼容的受体。
5. 展开 `#`，生成用户可预览的最终提交文本。
6. 生成结构化 `InteractionEnvelope`：原始草稿投影、实际文本、可见命令 ID（若有）、已解析受体 ID/类型、授权决定/范围、填充值键名、Session/Workspace 快照版本。API key、MCP 凭据等秘密绝不可进入 envelope。
7. 二次校验 workspace/session/plugin/权限仍有效，再提交命令或普通模型调用；权限/配置在编辑后发生变化时不得沿用旧校验。

**正文边界与结束信号：** 输入正文在用户按发送时封口；解析器不会等待模型决定何时停止读取输入，也不会把后续消息拼进当前命令。用户启动 `/目标` 后，行为运行期由模型/执行器的受管循环决定何时完成：模型通过已定义的结构化终止结果（完成、继续工具调用、失败、取消）驱动任务状态，执行器在不再有待执行调用且收到终态后关闭任务。不得把模型输出里自然语言的“完成了”当作授权、文件写入成功或终态证据。工具调用后还须复核 policy 与资源权限；任务有步数/时间限制、取消入口和失败终态。

若未来产品确认“命令正文在发送后继续由模型接收追加内容”，那应是独立的交互状态协议（需明确追加消息如何归属当前 commandId），不能由本语法隐式实现。

## 5. 授权与自动化策略

### 5.1 未使用 `/`

普通输入仍可请求模型回答，但不得因为语义像任务就自动创建系统自动化、后台任务跟踪、工作区扫描、文件访问计划或权限授予。无 `@` 的自然语言文件名不是资源授权；模型不得靠猜测搜索设备文件。合法 `@` 可以使该确切资源成为普通对话请求的显式上下文候选，但实际读取仍须由 File Manager/插件能力执行并复核授权。

### 5.2 使用 `/` 与显式受体

有效 `/命令` 明确选择了系统行为，允许命令对应的任务跟踪/生命周期进入自动化路径。对于声明为受管自动化的命令，显式 `@` 是本次请求可访问对象的白名单，也是最小权限授权意图来源。命令没有所需受体时应要求补充，不可悄悄退到默认 Workspace 或全局目录。

每次授权至少绑定：当前用户操作、commandId、sessionId、workspaceId、受体稳定 ID、能力集合、访问模式（读/写/执行）、有效期/任务生命周期与插件 owner。不能让正文中的“请访问其它文件”扩展名单；要访问新对象必须补充 `@` 并重新校验。插件实际能力仍必须已注册且 enabled；能力撤销立即使进行中的调用 fail closed。

为满足“明确 `/` + `@` 后可自动化”，可对用户明确引用范围内的低风险读取或明确列入命令策略的可逆操作自动授予本次任务范围许可。但 `/目标` 与 `@文件` 不是无限授权：删除、覆盖大量文件、公开发布、向第三方发送消息、转账、付费、触碰其它设备，以及系统/Android 权限均须沿用明确确认或 OS 授权。`ActionPolicy` 的 DENY/CONFIRM 不得被交互层跳过。权限确认必须说明动作、目标与可逆性。

### 5.3 两阶段复核与审计

授权分成“输入提及所表达的授权意图”和“执行前 policy/能力检查”两层。前者来自用户插入/确认的 `@` token；后者由对应服务端口执行，模型无权自签许可。执行前重新校验插件启用、Workspace 未归档、session 绑定、文件在 Workspace root 内、工具 enabled 和能力仍有效。

审计事件记录命令 ID、任务 ID、受体稳定 ID/类型、动作类别、policy 结果、时间与终态；不记录 API key、MCP secret、填充值明文或完整文件内容。用户可取消任务及撤销活跃授权；任务终态后授权自动失效。

## 6. 实时语法检测、高亮与辅助

解析器采用编辑器 token/AST 和稳定 UTF-16 range，不依赖逐字符正则拼接 UI，也不在模型侧进行语法校验。输入变化时增量重新解析；可先显示语法状态，再异步做目录/权限验证。发送时必须跑一次完整同步/强一致校验。

颜色应配合图标/文本状态，不能只依赖颜色：

- **蓝色：** `/`、完整命令名、分隔符、有效 `@` 受体/二级受体、已解析代词和有效 `#` 键均语法完整、实体唯一、类型/范围正确且权限当前通过。
- **红色：** 未注册/不完整命令、缺分隔符、错误层级、未知/歧义/越界/无权限受体、未解析或歧义代词、未定义填充键、权限在发送前撤销。红色 token 下显示简短错误原因，并可直接点击修正。
- **中性进行态：** 用户正在输入 `/`、`@` 或 `#` 的未完成片段，且尚未形成确定错误时保持中性/下划线，显示候选面板；不要在每个前缀字符上闪红。逾期或发送时仍不完整则转红并阻止提交。
- **需要用户确认：** 已解析但策略要求确认的动作使用独立确认状态（例如橙色图标/文案），不伪装成蓝色已授权。

辅助行为：

- `/` 后显示可执行命令目录，按当前插件状态、session/workspace 与能力过滤；选择项插入完整行为头及分隔符。显示命令输入 hint、所需受体类型、自动化/确认摘要。
- `@` 后按受体类型列候选；允许按名称、类型、Workspace 内路径筛选。支持“先选 Workspace 再选其内部项目/目录/文件”的二级选择。候选项展示所属 Workspace/父级和权限状态，避免同名误选。
- 可从最近一次明确提及中插入代词引用，但必须呈现回指目标；歧义时让用户点选绑定。
- `#` 后显示用户定义键列表，选中后插入原子 token；编辑阶段遮蔽敏感外观可选，发送前呈现最终展开内容。
- 发送按钮遇到红色错误禁用，并提供可访问性错误摘要；不静默删除错误 token 或偷偷降级成普通 prompt。

## 7. 推荐接口职责

这是职责建议，不是当前已存在的 API 定义：

- `InteractionIntegrationPlugin`：组装客户端输入目录/解析/分发能力，依赖 Model Adapter 与相应命令、实体目录，不实现 provider、文件系统或工具自身。
- `CommandRegistry`：按插件 owner 注册/撤销 descriptors；检查唯一名、schema、capability；暴露只读候选和按完整名称解析。
- `MentionCatalog` / `MentionResolver`：按 session/workspace 上下文列举并解析有类型实体；返回 stable ID、parent ID、允许子类型和状态，不返回未授权数据。
- `ReferenceAuthorizationService`：根据 command descriptor、明确 mentions、现行能力与 policy 计算最小范围授权，并在每个执行点复核。
- `AutomationTaskController`：创建有 commandId/Session/Workspace 绑定的任务，记录状态、取消、超时、终态和审计；任务日志与聊天正文分开管理。
- `FillValueStore`：本地管理填充值，提供版本化快照与按键展开；不向插件或模型暴露 store 本身，仅向本次提交提供已展开文本。
- `ComposerParser` / `InputEnvelope`：以稳定 token ranges 产出 parse diagnostics 和结构化发送快照；不拥有任何系统能力。

建议分离普通 `ModelGenerationRequest` 和命令/自动化请求，不能把 slash 头整体当 prompt 交给 provider。命令要么由命令 handler 执行直接动作，要么由受管 orchestrator 以结构化 context 调用 Model Adapter；两者均必须复用现有 Session/Workspace 与 Tool/File Manager 门禁。

## 8. 最小验收场景

1. 输入 `/目标：依据@产品工作区：自动化设计案执行自动化任务`：`目标` 精确命中注册项，工作区和内部设计案解析唯一，二级关系有效，最终 envelope 绑定当前 session/workspace；任务被跟踪，模型/工具循环以结构化终态结束后记录任务完成。
2. 输入 `/目`、`/目标任务`（若未注册）、`/目标依据...`（缺少分隔符）：提示红色错误，不能变成普通 LLM prompt，也不创建任务。
3. 不输入 `/`，仅写“扫描产品工作区的所有文件并自动执行”：不启动自动化跟踪，不授予扫描权。只有清晰的 `@` token 才能将一个具体受体纳入本次请求候选范围。
4. 引用不属于当前 Workspace 或越界文件时，候选不可选或发送失败；不通过更换模型、自然语言指代或 slash 命令绕过 File Manager。
5. 二级受体的父子归属不合法、名称歧义、代词无唯一前项、插件禁用或权限撤销时显示错误并阻止调用。
6. `#111` 精确替换预设值；`#11` 不匹配 `#111`，未知键不发送，值只在本地展开一次，并在发送历史中可检查实际内容。
7. 长时间自动化可取消；取消后不再派发新工具；任务已完成与模型生成已停止是不同状态，后者不能谎报操作成功。
8. 对删除/外发等高风险调用，即使存在有效 `/` 和 `@` 也仍触发策略确认；拒绝后不产生副作用。

## 9. 未决决策

- 命令目录主名与别名的 Unicode 规范化策略，以及是否支持英文 ASCII `:` 作为 `：` 的便捷别名。建议首期只接受明确注册的规范名，并以全角 `：`/空格作规范语法。
- 填充值是否提供可跨设备同步能力。首期建议仅设备本地，不同步，以免无意上传私人文本。
- 指代 token 是否采用可视 chip 还是普通文本加 range 标注。建议内部结构化，显示允许自然语言文字，歧义不自动猜。
- 首期自动授权策略矩阵应按具体命令/能力明确列出，不能以单个全局“自动授权”布尔值实现。
- 任务运行时和后台恢复策略需等任务系统/编排器设计后确定；本提案只规定终态、取消和权限复核要求，不宣称现有任务系统已经能满足。
